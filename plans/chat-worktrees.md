# Параллельные чаты в git worktree

Согласовано с владельцем 2026-11-01. Заменяет откаченный f8860c8: два чата не должны править одни и те же файлы.

## Поведение

- Обычный чат (не MCP) отправляет сообщение, папка проекта занята другим чатом или MCP-задачей, папка внутри git-репозитория → чат автоматически переносится в новый worktree и отправляет туда. Первый чат остаётся в основной папке.
- Worktree: `<корень репо>/.rundix/worktrees/<slug>`, ветка `rundix/<slug>` от HEAD основной папки. `/.rundix/` добавляется в `.git/info/exclude` общего git-каталога; `.gitignore` не трогаем.
- Незакоммиченные правки основной папки (tracked через `git stash create` + apply, untracked через копирование) переносятся копией; основная папка не меняется.
- В чате worktree видна метка ветки и кнопки «Влить» (коммит правок worktree + `merge --no-ff` в текущую ветку основной папки; при конфликте `merge --abort` и сообщение) и «Удалить worktree» (после подтверждения; чат возвращается в основную папку).
- Не git или git недоступен → прежняя ошибка, но с понятным текстом.
- MCP-задачи не меняются.
