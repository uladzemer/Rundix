# Rundix без окна: фоновый сервис с пулом и изоляцией по проектам

> Рабочий план, начатый 20 октября 2026 года. Отметки ниже фиксируют ход той работы; актуальное состояние и ограничения следует сверять с исходниками, CHANGELOG и документацией в standalone/docs.

Цель: Claude Code ставит и ведёт задачи Codex через MCP и при закрытом VS Code; история задач и чатов сохраняется, и при открытии VS Code Rundix показывает их как обычные чаты. При нескольких окнах VS Code (разные рабочие столы, разные проекты) у каждого проекта своя связь — задачи и чаты не смешиваются.

Решения владельца (2026-10-20): сначала режим без окна, затем Gemini/Antigravity (plans/gemini-antigravity.md); пул аккаунтов переносится в фоновый сервис; обязательна изоляция связи по проекту/рабочей области; Windows обязательно, macOS — по возможности тем же кодом.

## Финишная черта (проверяемо)
1. VS Code закрыт: Claude в проекте A делает submit → wait_task (или фоновый `--wait`) → отчёт → close_task; Codex работает через пул с ротацией.
2. Открыты два окна VS Code на проектах A и B (можно на разных рабочих столах), в каждом своя сессия Claude: задачи Claude из A видны и исполняются только в контексте A, из B — только в B; list_tasks в A не показывает задачи B; закрытие или перезагрузка окна A не трогает B.
3. После открытия VS Code на проекте A его задачи, сделанные без окна, видны в панели MCP и истории; чат задачи открывается, продолжается, отвечает на вопросы.
4. Перезагрузка окна, перезапуск сервиса и Windows не теряют задачи (recovery как сейчас).
5. Тесты: синтетика сервиса и маршрутизации, host-тест «сервис + два окна», живой прогон на Windows; на macOS — как минимум синтетика и упаковка.

## Ключевая модель изоляции (предложение, уточнить после исследования)
- «Пространство» = рабочая область VS Code / корень проекта Claude (канонический путь git-корня или папки workspace).
- Один фоновый сервис на пользователя ОС, внутри — независимые пространства: своя очередь задач, свои сессии, свой bridge-адрес (или маршрут), общий только пул аккаунтов и лимиты.
- Stdio MCP-сервер, запущенный Claude Code, определяет своё пространство (cwd процесса / переменные окружения Claude / MCP `roots`) и разговаривает только с ним.
- Окно VS Code подключается к сервису как клиент своего пространства; нет сервиса — поднимает его.
- Задача вне своего пространства (чужой projectDirectory) — явный параметр или отказ, а не тихое смешивание.
