# Модель и глубина MCP: выбор в панели и показ в задачах

Согласовано с владельцем 2026-11-24. Развивает настройки `rundix.mcpDefaultModel` / `rundix.mcpDefaultEffort` из 0.4.19.

## Поведение

**A. Выбор в панели MCP.** В панели «Задачи MCP» — блок «Модель для новых задач» с двумя списками.

- Модель: «Автоматически» (встроенное предпочтение GPT-6.2 Sol · Medium, пользовательская настройка не задана), «Как в обычном чате» (пустая строка), затем модели каталога подключения. Сохранённая модель, которой нет в каталоге, остаётся видимой с пометкой «недоступна».
- Глубина: «Авто» и значения, которые поддерживает выбранная модель. Смена модели сбрасывает неподдерживаемую глубину в «Авто».
- Выбор сохраняется сразу в пользовательские настройки (те же два ключа), в сервисном режиме — после синхронизации с сервисом. Действует на новые задачи; уже созданные не меняются.
- Каталог запрашивается только при запущенном мосте MCP. Без каталога блок показывает текущие значения и подсказку; ошибка загрузки не ломает панель и не теряет черновики.

**B. Показ модели задачи.** Запись последнего подтверждённого хода `lastSelection: {model, displayName, effort, turnId}`.

- Источник — параметры, реально отправленные в `turn/start`, а не текущие настройки.
- Видна в карточке задачи панели MCP, в шапке чата задачи (оконный и сервисный режимы), в `get_task` / `wait_task` / `list_tasks`.
- У задач без записи (старые, ещё не стартовавшие, импортированная история) строка не показывается — значение не выдумывается.

## Границы

- Always: существующие ключи настроек, только пользовательский уровень; обе локали; синтетические данные в тестах; ограниченные таймауты; результат привязан к своему клиенту, пространству и сессии.
- Never: менять параметры RPC `thread/start` / `turn/start`; логировать каталог, задачи, пути; новые ключи настроек сервиса; настройки уровня проекта; публикация в Marketplace и установка сборки.
- Сбой записи выбора не должен влиять на доставку хода.
